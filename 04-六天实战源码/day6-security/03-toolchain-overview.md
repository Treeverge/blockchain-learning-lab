# Day 6 · 本地工具与后续路线

本章用浏览器体验控制权和账本，再用Python与隔离Solidity VM验证；无需真实钱包或测试网。

## 按任务选择工具

| 任务                 | 项目使用方式                                                                                     |
| -------------------- | ------------------------------------------------------------------------------------------------ |
| 首次理解原理         | 打开重入网页，逐帧查看回调与临时状态                                                             |
| 复核整数模型         | Python标准库 / Node内置测试，无需安装框架                                                        |
| 手动观察真实合约     | Remix本地VM，选择与测试一致的solc 0.8.20                                                         |
| 自动复核真实行为     | solc + ethers + Ganache本进程VM，版本固定，见Day6 README                                         |
| 将来维护更大合约工程 | 可评估Hardhat或Foundry；以所选版本官方文档配置编译、测试和部署，不把插件命令当成所有版本内置命令 |

这些工具解决不同任务，不构成必须依次升级的阶梯。本项目的公开网页由GitHub Pages托管；合约验证不需要常驻节点。

## 用测试表达安全问题

- 重入：比较外部调用前后的共享状态，检查所有能重入的入口。
- 算术：Solidity 0.8系列默认检查溢出，但unchecked、类型转换和业务单位仍需单独核对。
- 权限：写出谁能执行关键操作，并测试允许与拒绝路径。
- 排序与报价：用过期报价、最小接收量和冲突交易测试风险；交易隐私不能保证完全消除排序风险。
- 外部价格：测试价格来源、更新时效、异常值和极端流动性；单一平均策略不等于完整防护。

本轮具体自动验证范围是重入、偿付、失败传播与账户执行边界；未将上面的所有类别实现成完整安全套件。

## 六章串联

1. 哈希能检测变化，不能证明录入事实本身真实。
2. 节点比较有效历史，等工作分叉可以暂时并存。
3. 签名说明授权身份，输入仍须存在且未花费。
4. 原生余额、代币存储和执行费用分别核对，失败有不同边界。
5. 交换、LP和借贷逐资产对账，价格变化可能造成损失。
6. 外部调用交出控制权，旧状态与失败传播决定最终资金。

下一步可用项目Issue提交一个失败样例：给出初态、操作、预期账本和实际账本，比只写“感觉不安全”更容易复核。
