# Day 5：DeFi —— 交换、流动性与借贷

这章从账本出发：每次操作都要回答资金来源、去向，以及失败时谁承担损失。只使用教学资产，不连接真实钱包。

下方不带路径的 Python 示例命令在本目录执行；“验证”一节的测试命令在仓库根目录执行。

## 先体验网页

双击 `../../03-演示文稿/defi-exchange.html`，或从根目录学习首页进入。

六步流程：预测 → 交换 → 比较深度 → 追踪手续费 → 报价变化 → 解释题。浏览器使用 BigInt；每个资产采用 6 位小数。

接着打开 `../../03-演示文稿/defi-liquidity.html`：投入两种资产，获得 LP 份额，模拟普通交易和实际套利，退出后与同批资产原样持有比较。手续费已经包含在退出资产中，不额外加一次。

无手续费、没有额外普通交易的对照情景：投入各 100，外部价格从 1 变为 4，套利后约可退出 50 A + 200 B，价值 400 B；直接持有价值 500 B，相对差距约 −20%。这不代表相对初始 200 B 的本金损失。

网页版省略最小锁定份额，由初始 LP 保持池子资产。参考公式只适用于理想条件；实际差距包含费率、交易路径和整数舍入。可展开网页对账表检查套利资金来源，模型见 `../../assets/js/lp.js`。

源码对照可运行 `python -X utf8 04-lp-vs-hold.py`。它用整数账本复算上面的**无手续费理想情景**：投入各100后得到100/1100份额；外部价格变为4时池子仍各有1100。套利者向池子付1100 B换得550 A，再把550 A交给外部市场换回2200 B，净赚1100 B。LP按份额退出得到50 A + 200 B；同价估值400 B，对比原样持有的500 B是**相对持有−20%**。

脚本逐项核对池子、LP钱包、套利者和外部市场的 A/B 数量。先预测：如果只改价格而不套利，LP可退出资产会变化吗？再看 1100 B 从谁的钱包流出，2200 B 由谁支付。这个固定方向的例子不包含普通交易、手续费、Gas或完整市场搜索；也不采用下面 Solidity 合约的最小锁定份额。不要把三种模型的份额数量直接相加比较。

## AMM：用同一规则验证结果

```powershell
python -X utf8 01-amm-demo.py
```

Python 只使用标准库。每次比较从独立新池子开始，不把连续交易误当成同初始条件。

交易前储备 x、y，输入 a，有效输入 e = a × (1 − f)：

```text
输出 = y × e / (x + e)
新储备 = (x + a, y − 输出)
```

完整输入进入池子，手续费留在储备中。0.3% 手续费、1000/1000 初始储备、输入 100 A，输出 **90.661089 B**。

Python 交易方法接受最小单位整数：`100 * SCALE` 表示 100 A。初始化方法的 `1000` 表示 1000 个代币。输出只在最后向下取整。

挑战：

1. 比较 100/100 与 10000/10000 两个池子，同样输入 100 A 为什么输出不同？
2. 将费率改为零，观察 k 是否严格相等，解释整数舍入影响。
3. 报价后先执行另一笔交易，再用原报价的 99.5% 作为最小输出，解释失败原因。

## Solidity：相同报价，额外观察 LP 份额

将 `02-simple-dex.sol` 复制到 Remix，用 Solidity 0.8.20 或兼容编译器，部署到 Remix VM。不要选择真实网络。

| 操作 | 参数（最小单位） | 观察 |
| --- | --- | --- |
| `faucetA`、`faucetB` | 各 `10000000000` | 账户各获得 10000 个教学代币 |
| `addLiquidity` | `1000000000, 1000000000` | 初始储备各为 1000，获得 LP 份额 |
| `getAmountBOut` | `100000000` | 报价为 `90661089`，即 90.661089 B |
| `swapAtoB` | `100000000, 90207758` | 最小输出按原报价的 99.5% 向下取整 |
| `lpShares` | 当前 VM 账户地址 | 查看份额 |
| `removeLiquidity` | 部分已有份额 | 按份额取回两种资产，包含留池手续费的影响 |

交易函数现在有输入和最小输出两个参数，旧版单参数操作已不适用。首次 LP 份额按两种资产数量乘积的平方根计算，锁定 1000 个最小份额；后续必须按当前储备比例投入，过小投入和零输出被拒绝。

这是内部余额模型，不是真实 ERC-20 集成。严格比例投入不会自动退回多余代币；真实路由流程与本例不同。无常损失需要引入外部价格、套利及持有基准，本版尚未提供完整实验。

## 借贷：抵押不足时，账本不能凭空补钱

先打开 `../../03-演示文稿/defi-lending.html`：从存款人提供现金开始，锁定抵押并借款，改变价格，再选择补抵押、还款或由清算者实际付款。

默认锁定 3 C、价格 100 B/C、借款 180 B：健康因子约 1.333333；75 B/C 时刚好为 1，不能清算；70 时低于 1，但抵押仍足以覆盖还款和 5% 奖励。60 时按本教学清算规则只能偿还 171.428571 B，坏账为 8.571429 B。价格修改本身不转移资产。

网页与 Python 使用 `tests/lending-vectors.json` 核对相同清算结果。两者均省略利息和部分清算；全额关闭、固定奖励及还款上限是教学设定。借款现金保留在钱包，未模拟花掉借款。债务是债权，不是新增现金。

```powershell
python -X utf8 03-lending-demo.py
```

明确区分抵押数量、单价与价值。借款上限使用抵押价值的 2/3；清算健康因子使用抵押价值 × 0.8 / 债务。这些是教学参数。

重复借款累计旧债务；还款检查真实钱包余额，并在清偿后退回抵押。清算者实际支付现金，收到抵押资产。抵押不足以覆盖债务与奖励时，实际可偿还额受抵押价值约束，其余记录为坏账，不能显示负数“剩余资产”。

模型省略利息、部分清算、真实预言机、存款退出和费用，不模拟完整协议。这里的坏账是存款可回收资产的缺口，不是凭空增加的现金。

闪电贷未实现为可执行实验。交易原子性不等于协议零风险，不应由这段说明推导资金安全结论。
