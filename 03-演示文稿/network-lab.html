传播交易

固定难度 · 1 位零

先按主线投递：A、B 收到 X；C 收到 Y。待确认不等于已扣款。

待确认池采用先收到的冲突候选，这是本地策略；它不会替其他节点确认交易或决定历史。

A 把 X 挖进区块，C 把 Y 挖进另一个区块。再把 A 的链给 B，形成 A / B 与 C 的分歧。

有待确认交易就放一笔；没有则挖空块。每块真实尝试 SHA-256，最多 100000 次；空块没有费用或奖励。

预测：A、B 两个节点都选 X，C 一个节点选 Y。把 C 的分叉给 A / B，两个节点会接受吗？

只有完整有效、累计工作更多的候选才替换当前链。等工作保留当前链；节点数量不参与这个选链规则。

C 再挖一个空块，Y 分支的有效工作从 16 增至 32。传播后，A / B 要撤下 X，并重放 Y。

对照 Bob、Eve 和费用账户：旧分支的输出及费用必须撤下。被撤下的交易仍需重验输入，不能直接加回余额。

挑战：让旧交易回到待确认池

重置后，只把 X 给 A，再让 A 挖一块。C 不接收交易，连续挖两个空块，然后把 C 的链给 A。观察 X 是否恢复待确认、费用是否回到 0；再让 A 重新挖出 X。使用前几步的自由操作按钮完成。

Eve 用自己的私钥签 Alice 的 X 主体，再为它挖一块和两个空块。默认主线下，它比合法链多一个块。

签名本身与工作量证明都可能有效。节点还必须逐块验证所有权、未花费状态、金额与完整交易摘要。

每个非创世有效块记 16 单位期望工作；与本次尝试次数分开。

    确认过的交易，还可能被撤下吗？

    这里的确认表示交易在节点当前选中的链里。未来更多有效工作可能改变它的历史；节点要恢复旧输入，再执行新分支，不能把两份冲突交易的输出叠加。

    试着解释：X 被撤下后，为什么不能立刻再确认？

    Y 已在新链花掉同一笔 70。X 的 Alice 签名仍有效，但输入已不存在于新链 UTXO 中。若撤下的是一份不冲突且仍可花费的交易，模型会把它放回待确认池，等待重新打包。

    计算规则与模型边界 ＋

    这是一个浏览器里的三个独立节点快照，没有 P2P 服务、真实矿工、钱包连接或资产。传播由按钮控制，不模拟网络时延、带宽、攻击者算力、手续费市场或最终性概率。

    复用真实 P-256 签名、BigInt UTXO 和 SHA-256。创世锚点绑定共同初始账本；后续块绑定完整交易与公钥、签名材料的摘要。签名 / 地址 / 序列化不是 Bitcoin 实现。

    固定一位十六进制前导零，非创世有效块各记 16 单位期望工作。最多 8 块；等工作保留当前链，更多有效工作才切换。先验证区块和所有交易，再比较工作。验证失败的长链没有有效累计工作。

    重组使用共同初始账本完整重放，小链便于核对；真实实现会使用更复杂的数据库与撤销机制。孤立交易重新校验后才进入待确认池，池内冲突采用先保存策略。费用账户是教学对账设定；空块没有费用和奖励。
