试着回答，再展开解释

重算哈希只能让 ID 与内容对应；签名检查内容是否获密钥授权；所有者检查这个密钥能否花该输入；UTXO 检查输入是否还未花费；共识让节点对确认历史收敛。它们各自解决不同的问题。

计算规则与模型边界 ＋

使用原生 Web Crypto ECDSA P-256 / SHA-256。Day 3 Python 使用 secp256k1，本网页不是比特币交易、签名或脚本实现。身份指纹不是比特币地址；教学 ID 只取交易主体的 SHA-256，不包含签名，与 Bitcoin txid / wtxid 不同。

主体固定编码为 ["UTXO-LAB-v1", 输入引用数组, [归属指纹, 整数金额字符串] 输出数组, 手续费字符串]，使用 UTF-8 JSON。所有输入对同一完整主体签名；同一发送者的签名可用于多个输入。金额以 6 位精度整数计算。

签名使用浏览器 ECDSA 的 64 字节原始格式。创始输出是实验种子；费用归集只是对账规则。省略 Bitcoin 脚本、真实网络、区块确认、coinbase、持久化、分叉回滚及手续费市场。
