# 重入与偿付能力实验

服务已学过账户回滚的中文初学者。主任务是解释外部调用期间旧债权为何能被重复读取，以及失败传播范围如何决定最终状态。

推荐逐步调用轨迹配合资金账本；单纯播放动画不容易复核中间状态，直接要求 Remix 则增加第一次体验的门槛。网页保持既有浅色编辑式工作台、蓝色动作、系统中文字体和等宽数字。四阶段：正常提款、重复提款、两种防护、失败传播。桌面双栏，手机单栏。轨迹可前后翻阅，注明临时快照；最终账本始终另列。减少动态效果时保留全部文字和数值。

初始银行现金6、Alice债权3、Bob债权2、攻击合约债权1；外部接收余额均0。每次实验重新建立同一初态，攻击者的1已经存入银行，提款事务失败不会撤销这个先前存款。最多接收1至8次。银行现金和外部余额总计恒为6；债权不是额外资产，偿付缺口=max(债权合计-银行现金,0)。

三种提款实现：有漏洞版本先转账再清债权；CEI先清债权再转账；为隔离锁的作用，lock版本加锁但仍先转账后清债权。原Solidity SafeBankWithLock保留CEI加锁，另加LockOnlyBank作教学对照，明确不是完整安全审计。

每个递归调用有快照，失败恢复该调用及后代状态。攻击回调可以捕获内层withdraw失败并正常返回，也可向外传播；外层require检查call失败。捕获时安全银行只付款1；传播时安全银行整笔提款回滚。接收者主动拒收也回滚。轨迹保留失败前的临时状态，最终状态只提交成功分支。

JavaScript/Python均是有界教学执行器，不模拟EVM、真实资产、交易签名、Gas或nonce。Solidity在隔离本地VM验证真实call、事件回滚、资金/债权、解锁和交易费用，不与网页定额对应。网页不引入服务器、钱包或外部依赖。
