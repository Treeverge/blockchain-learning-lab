# 学习与验收说明

[打开学习工作台](../learning-path.html) · [返回首页](../index.html)

网页实验是起点。一次学习至少留下三样东西：操作前的预测、操作后的账本解释、一个能复现边界的测试或失败样例。

## 推荐顺序

| 站点       | 主要问题                         | 应留下的解释                                  |
| ---------- | -------------------------------- | --------------------------------------------- |
| 哈希       | 链接自洽等于事实真实吗？         | 修改、重算、挖矿、传播各改变哪一层            |
| 签名与UTXO | 有效签名一定能花钱吗？           | 70输入如何产生45、24与1；授权与可花费性分开   |
| 节点与分叉 | 节点更多就能赢吗？               | 待确认、等工作、重组如何改变历史与费用        |
| 账户       | 执行失败究竟恢复什么？           | 纳入前拒绝与纳入后失败的nonce、费用、业务状态 |
| 交换       | 没有手续费就能按初始比例成交吗？ | 平均成交价、完整输入留池、过期报价拒绝        |
| LP         | 赚到手续费就一定跑赢持有吗？     | 套利资金来源、份额、同价比较与费用不重复计入  |
| 借贷       | 可以清算就不会亏钱吗？           | 现金、债务、抵押与奖励后的坏账分别核对        |
| 安全       | 总钱数守恒就说明安全吗？         | 外部回调、旧债权、防护方式与失败传播范围      |

先学签名再学分叉，是为了能读懂区块里的交易。它对应原Day3在Day2之前；六天源码目录编号保留，学习无需按日历天数完成。

## 怎么判断这一站值得继续深入

1. **先预测。** 写下改变输入后哪些余额或状态会变，哪些不变。不要先展开答案。
2. **运行并对账。** 看交易来源与接收者，分别计算每种资产总量。债权、费用、估值不是可以随意相加的同一种余额。
3. **制造失败。** 使用越权、重复输入、过期报价、边界价格或回调失败，观察失败发生在哪层。
4. **写解释。** 用“谁发起、校验什么、何时写入、失败恢复到哪里”组织句子；写出模型没有覆盖的部分。
5. **对照标准。** 情景题答对后，把自己的解释逐条对照本站三条标准，明确点击确认。
6. **补源码测试。** 选择本站挑战，在副本或新增测试中检验一个此前没有覆盖的条件。

“已确认自检”只记录第5步，由学习者自行确认；不代表源码挑战已经运行，也不是认证掌握。空白解释不能确认，但任意非空文字也不会被页面判为有质量的论证。质量需要你按标准核对，或请别人复核。

## 开始源码练习

在项目根目录先运行现有测试，确认基线。浏览器模型测试用Node内置测试器，无需安装框架：

```powershell
node --test tests/amm.test.cjs tests/lp.test.cjs tests/lending.test.cjs tests/chain.test.cjs tests/utxo.test.cjs tests/network.test.cjs tests/account.test.cjs tests/security.test.cjs tests/curriculum.test.cjs
python -X utf8 -m unittest discover -s tests -p "test_*.py"
```

从工作台的“读模型”与“看已有测试”进入对应文件；不要删除或修改已有断言来掩盖失败。新增 `tests/my-learning.test.cjs`，先写一个你预测的结果，再运行它。需要扩展模型时，先复制源码并让你的新测试引用副本。

例如安全实验增加7 G初态，不必更改默认6 G模型，只需在新测试里给状态补足现金与债权：

```javascript
const test = require("node:test");
const assert = require("node:assert/strict");
const S = require("../assets/js/security.js");

test("更多初始存款仍不能重复支付旧债权", () => {
  const initial = S.createState();
  initial.cash = 7n;
  initial.claims.Alice = 4n;
  const result = S.run(initial, { mode: "cei", maxPayouts: 7 });
  assert.equal(result.state.wallets.Attacker, 1n);
  assert.equal(result.state.cash, 6n);
  assert.equal(S.totals(result.state).assets, 7n);
});
```

```powershell
node --test tests/my-learning.test.cjs
```

再独立完成工作台的漏洞版本、8次失败传播挑战，并解释它与上述CEI结果为何不同。测试通过不能替代解释，也不能证明所有攻击变体都被覆盖。

LP下跌挑战中的价格0.25不属于当前网页预设；需先在源码副本扩展 `setPrice` 的允许列表，然后测试套利与份额计算。网页仍只使用当前已验证的预设，不把练习中的扩展当成现有功能。

真实合约练习使用各章README中的本地VM步骤。JavaScript教学模型与真实Ethereum / Bitcoin在曲线、交易序列化、Gas、网络与协议规则上有明确差异；把相同原理与相同实现分开。

## 记录与分享

工作台保存当前浏览器源下的答案、解释和自检标记，不上传。文件、网站、其他浏览器不保证共享。记录不可读或版本不兼容时保留原始数据，仅在本页继续；保存失败也会提示。可导出Markdown笔记留存，当前不支持导入。

打开多个学习工作台时，避免同时修改记录；当前没有跨标签页合并。导出的笔记比浏览器缓存更适合作为长期学习材料。

分享问题时附上：初始状态、具体操作、预期状态、实际状态、你对差异的解释，以及可复现的最小测试。这样的记录能让别人检验推理，也更容易发现教学模型的问题。
