# DeFi 交换实验：第一版设计

日期：2026-10-11

## 目标与范围

面向知道代币和交易概念、不了解 AMM 的学习者，用约 15 分钟解释交换报价、池子深度和手续费的资金流。交付静态网页与一致的 Python、Solidity 教学模型。先完成交换，再扩展 LP 加入退出、无常损失和借贷清算。

网页使用 HTML、CSS、原生 JavaScript，不引入前端框架或构建依赖。通过 GitHub Pages 发布；不连接钱包，不需要后台服务。虚拟资产只存在于访问者当前浏览器会话，刷新恢复初始状态。

用户于 2026-10-11 在本次对话明确授权助手全权执行。助手负责代码、验证及发布准备；只有账号或外部条件阻碍时才请求用户协助。

## 已核实的问题

- `01-amm-demo.py` 与 `02-simple-dex.sol` 从用户扣完整输入，只将扣费后输入加入储备，没有记录手续费去向。
- 有手续费的模型仍宣称交易前后储备乘积严格不变。
- Python 连续执行不同规模交易，混入了不同初始储备的影响；总结数值是固定文字，未从结果生成。
- Solidity 提前对扣费输入取整，小额交易报价受到额外精度损失影响。
- DEX 的 LP 份额只考虑 A，缺少比例约束及退出流程。先保留为待修教学示例，不作为新版交换实验的正确性依据。
- 借贷重复借款覆盖旧记录，清算可产生负剩余；这些内容在后续独立阶段修正。

## 统一交换规则

限定普通恒定乘积池、两种教学代币、固定手续费，无转账税和重基机制。

令交易前输入资产储备为 x，输出资产储备为 y，输入为 a，手续费率为 f：

- 有效输入：e = a × (1 − f)。
- 输出：b = y × e / (x + e)。
- 交易后实际储备：x' = x + a，y' = y − b。
- 手续费：a × f，留在输入侧池子储备中。它已经包含在 x'，不能再额外加一次。
- 无手续费且不考虑舍入时，x'y' = xy；有手续费时，储备乘积增加。
- 计算下一笔交易使用当前实际储备，不沿用初始化时的固定 k。

Solidity 与浏览器采用最小单位整数。手续费采用分子 997、分母 1000；最终输出向下取整：

`b = floor((a × 997 × y) / (x × 1000 + a × 997))`

浏览器用 BigInt 表示余额与储备。Python 采用相同整数公式；浮点数只用于显示比例。两种教学资产均采用 6 位小数。输入转换不能经过浮点乘法，最多接受 6 位小数。

每笔交易必须满足：钱包 A + 池子 A 守恒；钱包 B + 池子 B 守恒；钱包与储备非负。忽略 Gas、协议抽成及其他现实费用，并在页面注明。

## 教学流程

1. 初始池子 A=1000、B=1000，钱包 A=1000、B=1000；提示学习者预测输入 10 A 是否换到 10 B。
2. 展示报价并执行交易，比较初始边际价格、成交均价、手续费及交易后储备。
3. 从相同初始状态分别比较 10、100、500 A 的交易，解释规模对成交结果的影响。
4. 从相同 1:1 初始价格比较储备 100/100、1000/1000、10000/10000，解释池子深度。
5. 将手续费切换为 0 或 0.3%，追踪资产去向和 k 的变化。
6. 报价后模拟其他人先成交，再执行原交易；用最小接收量判断成功或失败。解释自身交易造成的价格影响与报价到执行期间的变化。
7. 完成三个解释题，并查看公式、模型边界与源码入口。

每步先预测，再操作，再展示解释。预测错误不阻止继续，也不提前显示答案。

上方显示实验问题和步骤；桌面中间并排显示钱包、池子和资金变化；下方展示公式与解释。窄屏按操作、结果、解释纵向排列，长整数可展开查看，不撑出横向滚动。

提供交易方向切换、金额输入、报价、执行、恢复初始状态、池子深度及手续费控制。改变池子深度或手续费视为切换独立实验，清空旧报价和历史并明确提示。

报价记录当时的池子状态和最小接收量。执行时重新计算输出；达不到最小接收量则拒绝且保持账本不变。模拟抢先交易使用单独虚拟参与者账本，资金来源可见。

拒绝零值、负数、超出精度、非法字符、余额不足、储备为空和舍入后零输出。失败原因显示在操作附近，不使用弹窗。有效交易记录前后状态，可重置但暂不提供撤销或持久化。

所有资源本地提供，不依赖 Google 字体或 CDN。网页清楚说明是本地教学模拟。

## 验收算例与检查

- 使用最小单位放大 10^6 的初始储备 1000/1000、输入 100 A、手续费 0.3%：输出 90.661089 B，储备变为 1100 A、909.338911 B。
- 同样输入、手续费为 0：输出 90.909090 B；说明整数舍入使乘积可能略增。
- 同初始状态比较不同输入，不使用连续交易结果冒充独立比较。
- 交易后逐资产守恒；手续费留池且没有重复记账。
- A→B 与 B→A 使用同一规则；失败不修改任何余额或储备。
- 抢先交易改变报价，低于最小接收量时原交易拒绝。
- Python、浏览器与 Solidity 的固定整数算例结果一致。
- 桌面和约 390px 窄屏浏览器检查布局、键盘操作、错误状态、重置和全部教学步骤。
