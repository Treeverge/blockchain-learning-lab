# 数字签名与 UTXO 实验

日期：2026-10-12。继续沿用学习工作台，补充交易授权与局部账本防重复花费的概念。

五步：公钥身份；选择输入、收款和找零；真实签名及攻击验证；确认并更新 UTXO；两份共享输入的有效候选发生冲突。

使用 Web Crypto ECDSA P-256 + SHA-256，原 Python 采用 secp256k1；浏览器签名不是 Bitcoin 签名/序列化实现。生成 Alice、Bob、Eve 三组临时密钥，私钥不可导出，不显示或存储；公钥导出为 raw 字节，指纹为公钥十六进制字符串的 SHA-256。刷新/重置重新生成。这只是角色演示，不是安全钱包。

初始 UTXO：Alice 30、70，Bob 50；总量 150，单位为 6 位精度的教学资产。交易绑定完整输入引用、全部输出归属和整数金额、手续费及版本域。教学交易 ID 是固定主体的 SHA-256，不包含签名；与 Bitcoin 的 txid/wtxid 不同。

默认使用 Alice 的 70，转给 Bob 45、手续费 1、找零 24。多个输入可合并；不允许重复引用、负数/零输出、超额输出、无效引用或缺失签名。所有输入都须签名；验签与公钥是否匹配 UTXO 所有者分开检查。

确认移除已消费输入、创建新的输出引用，手续费计入演示的费用归集账户。UTXO 总量 + 费用账户 = 初始总量。没有真实挖矿打包、coinbase、奖励、脚本引擎、网络、持久化或分叉回滚。

篡改收款人后可重算 ID，但旧签名无效；Eve 可以用自己的私钥生成有效签名，却不能授权 Alice 的输入。Alice 可签两份共享输入的不同交易，在确认前两者都满足各自校验；第一份消耗输入后第二份拒绝，签名仍可有效。真实网络还需要共识决定哪份进入历史，本实验只是一个本地确认账本。

签名操作会预先保存第二份冲突候选，便于按正常五步顺序验证双花。检查应显示当前账本语境；已确认交易的输入已消费不等于历史签名失效。

验证：不可导出私钥、真实验签、重哈希不能伪造签名、错误所有者、找零与费用守恒、多输入、重复引用、超额输出、重复确认与冲突拒绝，以及桌面/手机、本地双击、减少动态效果和在线部署。
